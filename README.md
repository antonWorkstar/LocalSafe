# Сховище — локальний менеджер паролів (PWA)

Застосунок, який користувачі встановлюють собі на телефон/планшет/ПК як звичайну
іконку. Дані шифруються (AES-256-GCM, ключ з майстер-пароля через PBKDF2)
і зберігаються **виключно на пристрої користувача** — жодних облікових записів,
серверів чи баз даних немає в принципі.

## Що тут є

```
index.html        — розмітка застосунку
style.css         — стилі
app.js            — вся логіка: шифрування, записи, PWA-реєстрація
manifest.json     — опис застосунку для встановлення на головний екран
service-worker.js — офлайн-кешування (після першого відкриття мережа взагалі не потрібна)
icons/            — іконки застосунку
```

## Модель безпеки (чому це не «звичайний сайт»)

- **Немає бекенда.** Хостинг лише віддає ці файли — так само, як флешка,
  підключена до інтернету. Немає коду, що виконується на сервері, немає бази
  даних, немає логінів на сервері.
- **Немає жодних мережевих запитів під час роботи.** У `index.html` встановлено
  `Content-Security-Policy` з `connect-src 'none'`, що технічно забороняє
  сторінці звертатись куди-небудь у мережу — навіть якщо в код колись
  випадково потрапить помилка чи стороння вставка, «злити» дані нікуди.
- **Шрифти й усі ресурси — локальні.** Жодних Google Fonts чи інших зовнішніх
  CDN, які могли б бути точкою стеження або підміни.
- **Після встановлення застосунок працює повністю офлайн** (service worker
  кешує всі файли при першому відкритті).
- Якщо хтось зламає сам хостинг — максимум, що можна зробити, це підмінити
  код застосунку для нових встановлень. Уже встановлені копії та вже збережені
  файли сховищ це не зачіпає, доки користувач не оновить застосунок.

## Розгортання (5 хвилин, безкоштовно)

### Варіант 1 — GitHub Pages
1. Створіть новий репозиторій на GitHub, завантажте туди вміст цієї папки
   (усі файли, включно з `icons/`).
2. Settings → Pages → Source: гілка `main`, папка `/root`.
3. Через хвилину застосунок буде доступний за адресою
   `https://<ваш-акаунт>.github.io/<репозиторій>/`.

### Варіант 2 — Cloudflare Pages / Netlify
1. Зареєструйтесь, натисніть «Deploy a new site» / «Create project».
2. Перетягніть цю папку (drag-and-drop) — деплой завершиться за секунди.
3. Отримаєте посилання типу `https://ваш-проєкт.pages.dev`.

Жодних змінних оточення, білдів чи налаштувань сервера не потрібно —
це просто набір статичних файлів.

## Як користувачі встановлюють застосунок

- **Android (Chrome):** відкрити посилання → з'явиться підказка
  «Встановити застосунок» / «Додати на головний екран».
- **iPhone/iPad (Safari):** відкрити посилання → кнопка «Поділитися» →
  «На екран Домівки».
- **Windows/macOS (Chrome/Edge):** іконка встановлення (⊕) з'явиться
  в адресному рядку праворуч.

Після встановлення застосунок відкривається окремою іконкою, без адресного
рядка браузера, і працює офлайн.

## Синхронізація між пристроями користувача

Це навмисно **не** хмарна синхронізація (щоб не було спільної точки атаки).
Користувач сам:
1. У застосунку тисне «Зберегти файл сховища» → отримує зашифрований `.json`.
2. Передає цей файл на інший свій пристрій будь-яким зручним способом
   (Google Drive, USB, AirDrop, месенджер — файл зашифрований, тому це безпечно
   навіть через хмарні сервіси).
3. На іншому пристрої, де застосунок вже встановлено, тисне «Відкрити файл
   сховища» і вводить той самий майстер-пароль.

## Оновлення застосунку в майбутньому

Якщо ви зміните файли й повторно задеплоїте — service worker сам виявить
нову версію (потрібно збільшити `CACHE_NAME` у `service-worker.js`,
наприклад на `vault-cache-v2`) і оновить кеш при наступному відкритті.
